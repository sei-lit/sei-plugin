ファイルの保存先の切り替え

  • 利用者が上げたファイルは、今は自前のファイルサーバーに置いている。これをクラウドのストレージに移す。
  • 上げる処理と、見せる処理の両方が変わる。上げる処理は、サーバーを通さずにストレージへ直接送る形になる。
  • 見せる処理は、期限付きの URL を返す形になる。今の固定の URL は使えなくなる。
  • 夜間のバックアップは要らなくなる。ストレージの側で版を残すため。
  • 決定: 古いファイルは一度に移さず、読まれたときに 1 件ずつ移す。

今の仕組み

利用者がファイルを上げると、アプリのサーバーが受け取り、ファイルサーバーの決まったフォルダに書く。書いた場所は DB に記録する。見せるときは、アプリのサーバーが DB から場所を読み、固定の URL を返す。ファイルサーバーの中身は、夜間のバッチが別の場所にまるごと写してバックアップにしている。容量が足りなくなると、手でディスクを足している。

変更後の仕組み

利用者がファイルを上げるときは、アプリのサーバーが上げ先の URL を発行し、利用者の端末がストレージに直接送る。書いた場所は今と同じく DB に記録する。見せるときは、アプリのサーバーが DB から場所を読み、期限付きの URL を返す。バックアップは、ストレージの版の機能で残すので、夜間のバッチは止める。容量は、ストレージの側で増える。

変わる所

上の 2 つの節で書いた違いを、処理ごとに表にした。変わらない所も、比べやすいように入れてある。DB に場所を記録する所は変えない。
