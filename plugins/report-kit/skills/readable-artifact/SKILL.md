# readable-artifact: 図を先に置き、文を削った Artifact を作る

## 目的

報告や説明のページは、文が多いと読まれない。部品どうしの関係や前後の違いを文と並べたラベルだけで書くと、
読む人が頭の中で図を組み立てることになる。このスキルは、書く前に「何を図にするか」を決め、
文の量に数の上限を置き、描画した画面と検査のスクリプトで確かめる手順を決める。

組み込みのスキルとの分担:

| 決めること | 従うもの |
| --- | --- |
| 何を図にするか、文をどこまで削るか、どう確かめるか | このスキル |
| ページの骨組み・色の変数・テーマ・外部の読み込み・フォント | artifact-design |
| SVG の描き方の原則（figure と figcaption、role="img"、文字の大きさ） | artifact-diagramming |
| 数のグラフ | dataviz |

スクリプトと雛形の場所（以下、プラグインルートからの相対パスで書く。Claude Code では先頭に `${CLAUDE_PLUGIN_ROOT}/` を付ける）:

- `skills/readable-artifact/scripts/check_artifact.py` — 文の量と公開の決まりの検査（Python 3 の標準ライブラリだけ）
- `skills/readable-artifact/scripts/render_check.py` — 手元の Chrome で 4 通りに描画して撮り、崩れを一覧にする
- `skills/readable-artifact/references/figure-patterns.md` — 図の雛形（SVG の依存の図、前と後、流れ、時期、表、画像）
- `skills/readable-artifact/references/verify.md` — 描画を見る手段と、見る点

## 1. 書く前に決めること

1. **読む人が最初の 10 秒で知りたいことを 1 文で書く。** これが要点の 1 行目になる。
   「何が決まったか」「何をすればよいか」「何が変わるか」のどれかになることが多い。
2. **内容の形を見分けて、図を決める。** 1 つの節に 1 つの形を割り当てる。

| 内容の形 | 見分け方 | 使う図 | 雛形 |
| --- | --- | --- | --- |
| 部品どうしの関係（依存・呼び出し・包含） | 3 つ以上のものが「使う」「含む」「呼ぶ」でつながる | 箱と矢印の SVG。並べたラベルや色分けした箱で済ませない | figure-patterns 2 |
| 前と後（今と変更後、案 A と B の構成） | 「変わる」「なくなる」「新しく入る」が出てくる | 左右に並べ、同じ部品を同じ行に置き、変わる所だけ色 | figure-patterns 3 |
| 順番のある流れ（手順、通り道） | 「次に」「→」「のあと」が 3 回以上 | 左から右の箱と矢印（スマホでは上から下） | figure-patterns 4 |
| 時期 | 日付や月が 3 つ以上 | 横軸に時期の帯 | figure-patterns 5 |
| 選択肢の比較 | 2 つ以上の案を、同じ観点で比べる | 表（行 = 案、列 = 観点）。推す案に印 | figure-patterns 6 |
| 数の比較 | 比べる数が 4 つ以上 | グラフ（dataviz）か、数の列を揃えた表 | dataviz |
| 確かさの区分 | 実行した・読んだ・推定・未確認が混ざる | 文の後ろのラベル | figure-patterns 7 |

決まり（どれも、ページを見て合っているか判定できる）:

- 3 つ以上のものの関係は、並べずに線で描く。
- 前と後は左右に並べ、変わる所だけに色を付ける。変わらない所は灰色のままにする。
- 色は意味 1 つに 1 色。凡例は図の上に 1 行で置くか、図の説明で言う。
- 1 枚の図の箱は 12 個まで。超えるなら、まとまりの図と、まとまりの中の図や表に分ける。
- 図は `<figure>` で包み、`<figcaption>` に「何を見ればよいか」を書く。

3. **節の順番を決める。** 要点 → 一番大事な図 → 次に大事な図や表 → 分かっていないこと → 細かい根拠（折りたたみ）。

## 2. 文の量の上限

数は `check_artifact.py` のしきい値と同じ。文字数は空白を除いた字数で数える。

| 対象 | 上限 |
| --- | --- |
| 先頭（h1 から最初の h2 まで） | 要点の箇条書き 3 項目、各 1 文・60 字。ほかに日付・出典の 1 行（80 字）だけ |
| 1 つの節 | 図・表・折りたたみの外の文は 300 字まで。120 字を超える節は図か表を持つ |
| 節の始まり | 最初の図か表より前の文は 60 字まで（図を先に置く） |
| 図の説明（figcaption） | 2 文・100 字まで |
| 箇条書き | 1 項目 1 文・80 字まで |
| 表のセル | 1 文・60 字まで |
| ページ全体 | 折りたたみの外は 2000 字まで（表のセルと図の説明を含む） |
| 繰り返し | 要点・図の説明・本文で、20 字以上の同じ言い回しを 2 回書かない |

削り方:

- 細かい根拠・引用・手順・すべての案の比較は、`<details><summary>根拠（…）</summary>` に入れるか、別のページにする。
- 削っても残すもの: 確かさの区分（実行した・読んだ・推定・未確認）、判断の理由（なぜその形にしたかを 1 文）、
  していないこと（「ビルドはしていない」など）。理由は図の説明か、表の「判断」の列に置く。
- 図が言っていることを、本文で言い直さない。図の説明には、図から読み取りにくいことだけを書く。

書き方:

- 比喩や気取った言い回しを使わず、言いたいことをそのまま書く。主語と数を書く。
- 1 つの文に 1 つのことを書く。「〜ので、〜だが、〜する」とつながったら分ける。
- 名前は読む人が知っている言い方にする。内部の名前を使うときは、初めて出る所で 1 回だけ言い換える。

## 3. 図の作り方

- 雛形は `references/figure-patterns.md` にある。写して、部品の名前と座標だけを替える。
- 部品どうしの関係はインラインの SVG で描く。座標の決め方・矢印・色の変数・幅は figure-patterns の 2 の手順に従う。
- 前と後・流れ・時期は HTML と CSS だけで描ける（figure-patterns の 3〜5）。スマホの幅でも崩れない形にしてある。
- mermaid（`<pre class="mermaid">`）は座標を決めずに描けるが、色を変数から取れず、手元の描画の確認では描かれない。
  変わる所の色分けが要る図には使わない。
- 画像は data: の URL で埋め込み、1 枚 300KB・幅 1200px までに縮める（figure-patterns の 8）。

## 4. 確かめる

回数を決めて確かめる。直して確かめての繰り返しにしない。

1. **検査のスクリプト（何回でも）**: `python3 skills/readable-artifact/scripts/check_artifact.py <page.html>`。
   すべて ok になるまで直す。直さない項目があれば、その理由を報告に書く。点は 2 つの群で出る
   （readability = 文の量と図、publish = 公開の決まり）。
2. **描画を見る（1 回）**: セッションに ArtifactCheck（か Artifact の preview）があればそれを使う。
   無ければ `python3 skills/readable-artifact/scripts/render_check.py <page.html> --out <dir>` で 4 枚
   （PC とスマホの幅 × 明るいテーマと暗いテーマ）を撮り、崩れの一覧を読む。見る点は `references/verify.md`。
3. **直すのは 1 回**: 1 と 2 で見つけたものをまとめて直す。描画をもう一度見るのは、直した所が崩れていそうなときの 1 回だけ。
4. **公開した後**: 公開したページを開き、mermaid の図が描かれたかと、図の色が両方のテーマで読めるかを見る。

## 5. 既にあるページを直すとき

文を足して直さない。図に置き換えて、文を消す。

1. `check_artifact.py` をかけ、点と不合格の一覧を残す（直す前の記録）。描画も 1 回撮る。
2. 節ごとに、文やラベルの並びで書かれた「関係」「前と後」「流れ」「時期」を探し、1 の表で図を決めて描く。
3. 図にした内容の文を消す。図の説明には、図から読み取れないことだけを 1〜2 文で残す。
4. 要点を 3 項目にする。入らなかった項目は、本文の図か折りたたみに移す。
5. 上限を超える節は、根拠と細部を折りたたみに移す。2 の「削っても残すもの」は消さない。
6. もう一度 `check_artifact.py` をかけ、折りたたみの外の文の字数が直す前より減っていることを確かめる。
7. 描画を 1 回撮り、直す前と後の点と画像を並べて報告する。
