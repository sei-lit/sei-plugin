# book-skills

読んだ技術書の内容を、実行可能な手順・チェックリストとしてスキル化したコレクション。

## 設計方針

- スキルは本の「要約」ではなく「いつ・何を・どうやるか」の手順書として書く。
- 原文は転載しない。手法・フレームワークを自分の言葉で再構成し、出典(書名・著者)を明記する。
- 骨格(目次・主要概念の名称)は公開情報で裏取りし、細部は読者が書籍と照合する。
  照合未完了の項目には `[要検証]` マークを付ける。

## 収録スキル

| スキル | 元の書籍 | 内容 |
| --- | --- | --- |
| `good-code-review` | *Good Code, Bad Code* (Tom Long, Manning, 2021) | コード品質の6つの柱に基づくレビュー手順とチェックリスト |

## 使い方

```
/book-skills:good-code-review
```

または「Good Code観点でレビューして」のように書名・手法名で呼びかける。
