# ナビゲーション索引 (pull 優先)

> **典拠**: `04-large-codebase.md` §3「『読む』を『引く』に変える」を、索引の**置き場所とコスト構造**の観点で具体化したもの。push/pull の判断は本書、CLAUDE.md の読み込み挙動は Claude Code 公式 memory ドキュメントに従う。queryable 索引の prior art として indexion (https://github.com/trkbt10/indexion) を参照。

大規模コードベースで最も効く一度きりの投資。エージェントが「読む」前に「引ける」状態を作り、盲目的な grep + 全読みのトークンを構造的に下げる。ただし**引く索引をどこに置くか**でコスト構造が決定的に変わる。

## §1 原則: 索引は常駐させず pull する

> *The map is not the territory.* 索引はコードへの入口であって代替ではない。だからコンテキストに常駐させるのではなく、**外部に置いてオンデマンドで引く (pull)** のが原則。

索引の置き方は 2 つに分かれる:

- **push** — 索引をコンテキストに載せる (例: `CLAUDE.md` に地図を記載)
- **pull** — 索引を外部 (ディスク/サーバ) に置き、agent が必要時に照会する

push が構造的に抱える限界:

| 限界 | 内容 |
| --- | --- |
| 常駐課金 | 一度ロードされたら以降のターン全部で再課金。「1 回引きたいだけ」でも地図全体を運び続ける |
| 粒度が粗い | 「課金まわりだけ」を引けない。ファイル単位で丸ごと載る |
| 鮮度が手作業 | 静的スナップショットなのでコードからドリフトし、維持税が発生する |

pull はこの 3 つを構造的に回避する。**索引がコンテキスト窓の外に出る**ため常駐コストはほぼゼロ、クエリ単位課金で**コストがクエリ数 (= 実作業量) に比例**し (`04` §2 そのもの)、鮮度をコード由来にできる。

## §2 二段構え

| 段 | 手段 | 常駐コスト | いつ |
| --- | --- | --- | --- |
| **推奨** | queryable 外部索引 (pull / CLI・MCP) | ≈ 0、クエリ単位 | 規模が大きい・索引インフラを入れられる |
| フォールバック | 薄い `CLAUDE.md` 地図 (push) | 触った範囲が常駐 | 小〜中規模・ゼロインフラで済ませたい |

迷ったら pull を既定にする。push は「インフラを入れない時の下限の現実解」と位置づける。

## §3 推奨: queryable 外部索引 (pull)

コードからビルドした索引を、agent が `grep` / `search` / `explore` 等でオンデマンド照会できる **CLI または MCP サーバ**として公開する。索引の実体はコンテキスト窓の外にあり、**返ってくるのは的を絞った結果だけ**。

満たすべき性質 (特定ツールに依存しない要件):

1. **索引はコンテキスト外に常駐** — agent 側の常駐はツールスキーマ分のみ
2. **クエリ単位課金** — 「課金 → `src/core/billing/*`」のようなピンポイント結果だけが一時的に入る。索引サイズやセッション長ではなくクエリ数に比例
3. **鮮度はコード由来** — AST/トークン化 + git/mtime 等で索引を更新。手書きプロンプトのドリフトが起きない
4. **粒度が細かい** — 的を絞った問いに的を絞って答える (ファイル丸ごとではない)

委譲との相乗: 探索を `haiku-scout` に委譲する場合も、委譲先が pull 索引を引けば探索自体が安くなる (context firewall × index)。

> **prior art**: [indexion](https://github.com/trkbt10/indexion) — コードを KGF (Knowledge Graph Format) でトークン化し、`grep`/`search`/`explore` を **MCP/CLI** で公開、`plan reconcile` が git/mtime 証跡で鮮度を保つ。掲げる思想は *"The map is not the territory"*。上記 4 性質を満たす一例であり、本書はこの**性質**を推奨する (indexion 固有の採用を強制しない)。同種の MCP コードインデックス、あるいは「索引をディスクに持ち MCP/CLI で問い合わせる」薄い自作ラッパでもよい。要は**結果だけがコンテキストに入る**こと。

## §4 フォールバック: 薄い `CLAUDE.md` 地図 (ゼロインフラ)

pull 索引を用意できない/小〜中規模ならこれで十分。ただし push モデルなので**索引自身の常駐コスト**を抑える配置が要る。

### 読み込み挙動と配置 (常駐コストの源)

| 置き場所 | 読み込み | 常駐コスト |
| --- | --- | --- |
| ルート + 親の `CLAUDE.md` | 起動時に**先読み (eager)**。`/compact` 後も再注入 | **毎ターン課金** |
| サブディレクトリの `CLAUDE.md` | そのサブツリーを読んだ時だけ**遅延 (lazy)** | 触った範囲のみ |
| `@import` での分割 | eager 展開 (インラインと同じ) | **常駐削減ゼロ** |

- **ルートは薄い「地図の地図」に徹する** — トップ階層のディレクトリ地図と「詳細はどこか」のポインタだけ。公式目安 **1 ファイル 200 行以下**
- **詳細な領域別索引はサブディレクトリの `CLAUDE.md`(遅延)へ** — 常駐が「触った範囲」に比例し、リポ全体サイズに比例しない

### テンプレート (所在の地図に徹し、実装詳細は書かない)

```markdown
## ディレクトリ地図
- `src/api/` — 外部公開 API ハンドラ
- `src/core/` — ドメインロジック (副作用なし)
- `src/adapters/` — DB・外部サービス連携

## エントリポイント
- アプリ起動: `src/main.ts`  / HTTP ルーティング: `src/api/router.ts`

## 機能 → ファイル索引   ← 詳細化する領域は各サブツリーの CLAUDE.md へ
- 認証: `src/api/auth/*`, `src/core/session.ts`
- 課金: `src/core/billing/*`, `src/adapters/stripe.ts`

## 横断規約
- レイヤ依存方向: `api → core → adapters` (逆流禁止)
- 環境変数は `src/config.ts` に集約
```

### 生成と維持

- 索引づくりは判断ではなく**作業量タスク**。`haiku-scout` / `Explore` に委譲し、戻り値は `CLAUDE.md` ドラフトのみ要求 (生ツリーをメインに持ち帰らせない)。メインはドラフトを**監査**するだけ (`02`/`04` §3)
- **古い索引は無索引より有害**。所在が変わる変更 (ディレクトリ移動・機能追加) は同じ PR で `CLAUDE.md` を更新する

## §5 アンチパターン

| アンチパターン | 何が起きるか |
| --- | --- |
| pull 索引があるのに索引を `CLAUDE.md` に push | 常駐課金 + 手維持ドリフトを自ら招く。引けるものは外部索引へ |
| ルート `CLAUDE.md` に全索引を盛る | eager 先読みで毎ターン常駐課金、`/compact` でも消えず二次曲線を加速 |
| `@import` で分割して軽くしたつもり | eager 展開でインラインと同じ。常駐削減ゼロ。軽くするには nested(遅延)へ移すしかない |
| pull 索引の生ダンプをメインに持ち帰る | pull の利点を捨てる。結果 (所在) だけ回収する |
| 索引の生成/問い合わせをメイン高単価でやる | 作業量タスクを最高単価で課金。委譲する |
