# 描画を見る手段と、見る点

## 手段（上から順に、使えるものを 1 つ使う）

| 手段 | 使える場所 | 出るもの |
| --- | --- | --- |
| ArtifactCheck、または Artifact ツールの preview | Claude Code で、そのツールがセッションにあるとき | PC とスマホの幅 × 2 つのテーマ。はみ出し・テーマを無視した色・読み込みの失敗・コンソールのエラー |
| `scripts/render_check.py` | 手元に Chrome（か Chromium）があるとき | 4 枚の PNG と `report.json`（はみ出し・切れた文字・SVG の文字の重なりと箱からのはみ出し・縮みすぎた文字） |
| ブラウザを操作するツール（Claude in Chrome など） | 上の 2 つが無いとき | 手で幅とテーマを変えて撮る |

`render_check.py` について:

- 公開時に付く骨組み（doctype・viewport・余白の初期化）を包んでから描くので、公開後に近い見た目になる。
- テーマは `data-theme="light"` と `data-theme="dark"` を明示して描く。OS の設定には左右されない。
- headless の Chrome は 500px より狭い窓を作れないので、スマホの幅（390px）は iframe で作る。
- mermaid は公開先が描くもので、手元では文字のまま残る。mermaid の図は公開した後に見る。
- Google Fonts を読むので、ネットワークが無いと代わりのフォントで描かれる（文字の幅が少し変わる）。

## 見る点

スクリプトが一覧にするもの（一覧が空なら、目で見るのは下の「目で見るもの」だけでよい）:

- ページが横にはみ出していないか（スマホの幅）
- 横に動く箱の外で、画面の右端を越える要素が無いか
- 文字が `overflow: hidden` や `text-overflow` で切れていないか
- SVG の文字どうしが重なっていないか、文字が箱や図の外にはみ出していないか
- SVG の文字がスマホの幅で 9px より小さくならないか

目で見るもの:

- 最初の画面（PC で上から 800px、スマホで上から 700px）に、題名と要点と最初の図の頭が入っているか
- 図の色が暗いテーマでも区別できるか（変わる所の色が、背景と変わらない所の灰色の両方と違って見えるか）
- 前と後の図で、左右の同じ行に同じ部品が並んでいるか
- 矢印の向きが、凡例か図の説明で言った向きと合っているか
- 横に動く箱の中の図が、スマホの幅で最初に見える部分だけでも意味が通るか（起点の箱が見えている。figure-patterns の 2 の末尾）
